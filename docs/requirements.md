# DesktopWorld 要件定義

- 文書バージョン: 1.5
- 状態: layered child window の実行マニフェスト要件を明記
- 対象: Windows デスクトップ背景描画アプリケーション
- 描画 API: Win32 / Direct3D 11

## 1. 目的

Windows のデスクトップアイコン背面に、時刻・季節・観測地点に応じて変化する空を描画する。大気散乱の計算結果を時間サンプルとして保持し、隣接サンプルを補間することで、毎フレーム大気散乱を最初から計算する負荷を避ける。

将来の雲、天体、天候などの描画要素を追加できるよう、描画処理は Render Pass 単位で拡張可能にする。

## 2. 対象環境・制約

| 項目 | 要件 |
|---|---|
| OS | Windows 10 / Windows 11 x64 |
| API | Win32、Direct3D 11、DXGI、D3DCompiler |
| 言語 | C++20、HLSL |
| 外部レンダラー | 使用しない |
| GUI | Dear ImGui は開発用 Debug UI に限定 |
| 動作形態 | 常駐アプリケーション |
| 描画位置 | デスクトップアイコンの背面 |
| 初期表示 | 空半球。地面・建物・雲は初期スコープ外 |

## 3. 機能要件

### FR-01 デスクトップ描画

1. デスクトップアイコンの背面に描画する。
2. 描画ウィンドウはフォーカスを奪わず、通常のデスクトップ操作を妨げない。
3. デスクトップホストの取得・親子関係・Z オーダー・ウィンドウ破棄を Platform 層へ隔離する。
4. 旧構成ではアイコンを含む SHELLDLL_DefView の後ろにあるトップレベル WorkerW を使用する。Windows 11 24H2+ の raised desktop では Progman の WS_EX_NOREDIRECTIONBITMAP を検出し、0x052C(wParam=0x0D, lParam=1) を送って壁紙 WorkerW の生成を促したうえで、Progman を親とする独自の layered child window を SHELLDLL_DefView の直下へ配置する。
5. layered child window を利用するため、実行ファイルのアプリケーションマニフェストで Windows 10 以降への対応を宣言する。
6. 安全なデスクトップホスト構成を取得できない場合は、誤った Z オーダーへフォールバックせずエラーを通知する。
7. モニターを列挙し、仮想デスクトップ全体を1つの連続した描画面で覆う。全モニターに同じ空の環境を表示する。
8. 選択したデスクトップホストのクライアント領域が仮想デスクトップ全体を包含しない場合は、部分表示へフォールバックせずエラーにする。
9. Explorer の再起動やデスクトップホストの再生成後に描画ホストを再構築できること。
9. 初期の複数モニター方式は、仮想デスクトップ全体を覆う単一の子ウィンドウ・SwapChain・RenderTargetとする。モニターごとの独立環境・独立SwapChainは将来拡張とする。
10. モニター構成変更時は仮想デスクトップ範囲を再計算し、単一描画面を全体として再構築する。再構築に失敗した場合は部分モニターだけの表示を継続せず、描画面を停止して再試行する。

### FR-02 時刻と太陽位置

1. 内部時刻表現は UTC とする。
2. 通常動作では Windows のシステム時刻から UTC を取得する。
3. デバッグ時は固定 UTC 時刻を指定できる。
4. 観測地点の緯度・経度を設定できる。
5. 太陽方向は日付、UTC 時刻、緯度、経度から計算する。
6. 緯度・経度は設定ファイルに保存し、Release ビルドでも変更結果を使用できる。
7. UI で時刻を表示する場合、UTC かローカル時刻かを明記する。

### FR-03 大気モデル

1. 初期比較・動作確認モデルは Rayleigh / Mie 単一散乱とする。
2. 最終モデルは Bruneton 2017 系の事前計算方式を基準に、Rayleigh 散乱、Mie 散乱、多重散乱、地面反射、オゾン吸収を扱う。現行実装はRGB近似・低解像度・低角度サンプルのプロトタイプとし、参照実装と同等の精度を主張しない。
3. 大気の物理パラメータに依存する LUT と、太陽方向・時刻に依存する Sky View LUT を分離する。
4. 大気パラメータが変わらない限り、物理パラメータ依存 LUT を時刻ごとに再計算しない。
5. 大気 LUT はパラメータの識別子でキャッシュし、再起動後も再利用する。
6. LUT は HDR 浮動小数点フォーマットを基本とする。

### FR-04 時間サンプルと補間

1. 基本サンプル間隔は 60 分とする。
2. 日の出・日の入り付近では補間誤差を抑えるため、太陽高度に応じて自動的に短縮する。
   - |太陽高度| > 12°: 60 分
   - 6° < |太陽高度| <= 12°: 30 分
   - |太陽高度| <= 6°: 15 分
3. Debug UI から Auto / 60 / 30 / 15 分を選択できる。
4. メモリ上には現在時刻を挟む 2 サンプルを保持する。24 時間分の Sky View LUT を常時保持する要件はない。
5. 補間係数は UTC のサンプル時刻から算出する。
6. 補間は線形 HDR radiance 空間で行い、トーンマッピング後の色を補間しない。
7. サンプル間隔・時刻・生成条件を Debug UI で確認できる。

### FR-05 描画方式比較

| ID | 方式 | 用途 |
|---|---|---|
| A | 各出力ピクセルで3D scattering LUTを直接評価 | Sky View LUTと時間補間を省いた参照方式 |
| B | 現在時刻の Sky View LUT を生成して描画 | 現在時刻 LUT の生成・描画負荷の基準 |
| C | 2 つの Sky View LUT を Pixel Shader で補間 | Pixel 補間方式 |
| D | 2 つの Sky View LUT を Compute Shader で補間して描画 | Compute 補間方式。通常運用の初期既定値 |

A～D は同一の大気モデル・Static LUTを共有する。A は事前計算済み3D scattering LUTを出力ピクセルごとに参照し、B～D はSky View LUTを経由する。A と D の比較はSky View LUTの解像度・時間補間の誤差を比較するものであり、大気モデル自体の物理精度を保証するものではない。

### FR-06 フレーム更新

1. 環境サンプル生成とデスクトップ描画を独立して制御する。
2. Adaptive / Fixed / OnDemand の 3 モードを持つ。
3. Adaptive は薄明時に更新頻度を上げ、太陽高度が十分高い時間帯・夜間は更新頻度を下げる。
4. Fixed は設定 FPS で描画する。
5. OnDemand は明示的な描画要求がある場合だけデスクトップを描画する。
6. Debug UI の描画頻度とデスクトップ描画頻度は別管理とする。

### FR-07 設定

次の値を設定ファイルへ保存する。

- 緯度・経度
- 描画方式
- フレーム更新モードと FPS
- 時間サンプル間隔モード
- 大気パラメータ
- 露出

設定ファイルの既定位置は %APPDATA%/DesktopWorld/settings.ini とする。ファイルが存在しない場合は既定値を生成する。読み込み時に値を範囲検証する。

### FR-08 拡張可能な描画構造

1. RenderSystem が Render Pass を順番に実行する。
2. AtmosphereSkyPass を初期 Pass とする。
3. 将来の CloudPass / CelestialPass / WeatherPass / TerrainPass を追加できる。
4. Platform、Environment、Cache、Render の責務を分離する。
5. 初期段階で汎用レンダーグラフや過度なプラグイン機構は導入しない。

### FR-09 計測・検証

1. GPU Timestamp Query でStatic LUT全体、Transmittance、Direct Irradiance、Single Scattering、Multiple Scattering、Sky View生成、補間、描画を計測する。
2. GPU 計測は非同期取得し、計測のために GPU 完了待ちを入れない。
3. CPU 更新・描画コマンド投入時間と GPU 実行時間を別表示する。
4. B と D の比較により時間補間誤差を計測できる。
5. 太陽高度 -12°～+12° を重点的に検証する。
6. 太陽位置、サンプルスケジュール、補間係数、設定保存・再読み込み、Render Pass順序は自動テストする。
7. HLSL 全エントリーポイントを CI でコンパイル検証する。

## 4. 品質要件

- 大気パラメータが変わらない限り、Static LUT を再計算しない。
- Sky View LUT は必要なサンプル時刻が変化した場合のみ再生成する。
- OnDemand でデスクトップを描画しない時に不要な GPU 描画を投入しない。
- 描画ホストが失われた場合、無効 HWND へ描画し続けない。
- 設定不正、GPU リソース作成失敗、デスクトップホスト取得失敗を識別可能にする。
- Release ビルドは Debug UI がなくても設定ファイルから動作できる。

## 5. 初期スコープ外

- 雲、雨、雪、風などの天候
- 地形、建物、樹木
- 月、星、天体の描画
- ユーザー任意のメッシュ・マテリアル編集
- 高度な光条表現

## 6. 実装フェーズ

| フェーズ | 内容 | 完了条件 |
|---|---|---|
| P0 | 現行単一散乱の整合化、設定保存、Render Pass 分離 | Release で設定可能、サンプル更新が仕様どおり |
| P1 | Bruneton 系多重散乱 LUTの品質確立 | 事前計算・キャッシュ・参照画像・B対D誤差が検証済み |
| P2 | マルチモニター、Explorer 再起動復旧 | モニター構成変更・Explorer 再起動を検証 |
| P3 | 補間誤差・画像キャプチャ・性能計測 | 薄明を含むテスト結果を記録 |

## 7. 用語

- **Atmosphere LUT**: 大気の物理パラメータに依存する事前計算テクスチャ群。
- **Sky View LUT**: 特定の太陽方向・観測条件で見える空の radiance を格納する 2D テクスチャ。
- **Sample Pair**: 現在時刻を挟む 2 つの Sky View LUT。
- **Static LUT**: 大気パラメータが変化しない限り再利用できる LUT。
- **Dynamic LUT**: 太陽方向や時刻に応じて生成する Sky View LUT。
